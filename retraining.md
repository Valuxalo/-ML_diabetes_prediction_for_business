# При каких условиях требуется переобучение?
Можно выделить несколько триггеров.

- Плановое переобучение	Например, раз в 3–6 месяцев	Учитывать новые данные и поддерживать актуальность модели
- Снижение качества прогнозов	Recall или другая ключевая метрика опустилась ниже установленного порога	Снизить риск того, что модель будет пропускать клиентов, у которых есть диабет
- Изменение входных данных (data drift)	Распределение признаков, например возраста, BMI или уровня глюкозы, заметно отличается от обучающей выборки	Проверить, сохраняет ли модель качество на новых данных
- Изменение взаимосвязей в данных (concept drift)	Связь между признаками и целевым признаком изменилась	Проверить, не устарели ли закономерности, на которых обучалась модель
- Накопление новых размеченных данных	Появилась достаточная по объёму и качеству выборка новых примеров с известным целевым признаком	Обновить модель на более репрезентативных данных

# Процесс переобучения

# Какие метрики контролировать?

Метрика или показатель	Что контролируем	Почему важно
Recall	Долю положительных случаев, которые модель правильно выявляет	Низкий Recall означает больше пропущенных положительных случаев
Precision	Долю действительно положительных случаев среди прогнозов модели о положительном классе	Помогает оценить количество ложных тревог
F1-score	Баланс между Recall и Precision	Позволяет оценивать обе стороны качества
ROC-AUC	Способность модели различать классы	Помогает оценить качество ранжирования
Data drift	Изменения распределения входных признаков	Помогает заметить изменение поступающих данных
Доля пропусков и ошибок данных	Изменения качества входных данных	Позволяет обнаружить проблемы сбора и подготовки данных


Метрики качества необходимо рассчитывать на данных, для которых уже известен фактический целевой признак. Если результаты обследований клиентов не поступают в систему, достоверно измерить текущий Recall на новых данных не получится. В таком случае можно контролировать drift и качество входных данных, но это не заменяет проверку качества прогнозов по известным результатам.

# Как часто выполнять этапы?

Действие	Периодичность
Проверка полноты и корректности входных данных	При каждом поступлении данных
Мониторинг распределений признаков	Еженедельно
Пересмотр метрик качества на размеченных данных	Ежемесячно, если данные доступны
Плановый пересмотр необходимости переобучения	Раз в 3 месяца
Внеплановая проверка	При ухудшении метрик, существенном drift или обнаружении систематических ошибок
Проверка новой версии перед выпуском	При каждом переобучении
Проверка качества после внедрения	Сразу после запуска и далее по графику мониторинга


Периодичность должна учитывать доступность достоверной разметки и объём накопленных данных. Нет смысла переобучать модель каждый месяц, если за это время появилось слишком мало новых качественных примеров.

# По каким критериям принимать новую модель?
До начала эксперимента нужно определить критерии, по которым новая модель будет принята или отклонена.
Например:
- Recall не ниже установленного минимального значения.
- Recall новой модели не хуже действующей модели сверх допустимого отклонения.
- Precision и F1-score не ухудшились неприемлемым образом.
- Проверены ошибки на независимой тестовой выборке.
- Нет критических проблем с качеством данных и обработкой признаков.
- Результаты воспроизводимы, версия модели и обучающих данных зафиксированы.
Не стоит выбирать универсальный порог Recall без обоснования. Его следует определить исходя из требований бизнеса и результатов валидации. Для страхового процесса также необходимо проверить, что использование прогноза допустимо с точки зрения законодательства, конфиденциальности данных и правил компании.

Итог для документации: модель Random Forest переобучается планово раз в три месяца или внепланово при подтверждённом ухудшении качества, существенном изменении данных либо накоплении достаточного объёма новых размеченных примеров. После переобучения новая версия проходит независимую оценку и сравнение с действующей моделью. Если критерии качества не выполнены, новая версия отклоняется, а действующая модель продолжает использоваться.
